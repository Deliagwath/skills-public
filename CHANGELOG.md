# Changelog

All notable changes to this project are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). This project is not yet versioned; entries are grouped under **Unreleased** until a first tagged release.

## [Unreleased]

### Added

- `sp` logs its own calls, so a session can find its defects from evidence (Direction 005).
  - With `SP_LOG` set to an absolute path, every `sp` call appends one JSON line: time, duration, exit code, the workspace it resolved, cwd, argv, role, the harness session id when there is one, a checksum of `sp`, the answer's first line, whether it was cut, `ambiguous`/`broken` marks, and stderr; `SP_LOG_LEVEL=full` adds the answer. Every call is logged, usage errors and the `nav` alias included. `sp` runs itself as a child to do it, so the answer is unchanged; a log it cannot write costs one stderr line. Unset, nothing is written.
  - `sp log [<count>] [--all]` lists the failed calls, then the flagged ones, identical calls folded, each with a one-line rerun command. It reads the log from anywhere, with no workspace.
  - A new namespace, `debugging/`, and its first skill, `improve-sp`: it preflights the log loudly, picks a call, re-runs it, judges whether `sp` is at fault, and hands a defect to `bottom-up` with the record as its trigger. `bottom-up` lists a `sp log` record among its triggers.
  - `test.sh` clears `SP_LOG`, so fixture calls never reach a user's log, and gains the log's cases.

- One script reads and writes the waterfall (Direction 004, in progress: Tasks 022–026).
  - `nav` becomes `sp` (`facilitated-waterfall/scripts/sp`); `nav` stays as a link to it that answers only the read verbs. Every answer starts with a summary, wraps lines at 200 bytes and stops at 60 lines with a `+N more` line.
  - One resolver turns any reference into one doc: a kind-prefixed id (`task-084`, through `id:`, then kind directory and number), a path, or a legacy short id (narrowed by the upward rule; a bare number matches a file number digit for digit). Several candidates are reported as ambiguous, never picked. Sealing is the union of a successor's `supersedes`, the doc's own `superseded-by`, and a legacy `status: superseded…`. `trace` follows only a parent that sits higher, passing over probes and same-tier predecessors.
  - `sp check [<id>]` reports navigation-breaking problems (frontmatter missing or unparseable, a mapping or note in a link, missing `id`/`title`/`created`, ids not kind-prefixed or shared, broken or ambiguous links, `supersedes`/`superseded-by` that disagree) and drift (`status:` on a Direction, Epic, Task or Plan, downward `relates`, missing `intent:`, handbook entries outside the `note` contract, links into another workspace). Read answers add one `check` line when they list a malformed doc.
  - Write verbs: `sp new <kind> "<title>"` (numbered under a lock, kind-prefixed id, section skeleton, every FW and PW kind), `sp supersede <new> --of <old>` (both edges; nothing else on the old doc; idempotent), `sp relate <id> --to <id>` (refuses broken, ambiguous or downward links), `sp ledger implemented|done|not-achieved|reconcile` (ADR 0004 line formats; a probe close also sets its status).
  - Doc reads: `sp tree <id>` (descendants with their state from the ledgers, and the next free number per kind), `sp outline <id>` (headings and item ids with lines and sizes), `sp show <id> <heading|item>…` (the original lines of exactly those parts). `sp file <doc>` gives its trace and tree.
  - `sp migrate [--apply] [--settle <file>]` brings a repo to the shape `sp` reads, once: kind-prefixed ids and links, both supersession edges (including from a legacy `status: superseded by …`), notes moved out of `supersedes` into a `Supersession note:` line in the body, and frontmatter for a doc that has none. It previews on a copy (diff, before and after `sp check` counts) and writes only with `--apply`. A link no rule settles goes to a settle file that the user reviews; it is pre-filled from what the doc's body cites, but never applied unreviewed (ADR 0007). The resolver gains the not-downward rule: a bare id from a Direction or Task no longer matches a candidate on a lower tier.
  - `sp`, `sp help` and `sp --help` list every command; `sp <command> help` (or `--help`) prints that command's page: usage, what it reads and writes, examples and the next step. It works outside a workspace. An unknown command says `run sp help`.
  - Every FW and PW skill, and `to-waterfall`, writes through `sp` and runs `sp check` on what it wrote; artifacts are cited as `kind-NNN`. Supersession writes both edges (ADR 0005), and ids are kind-prefixed (ADR 0006). Without `sp`, the skills write by the same rules by hand.
  - `install.sh` declares mdq and mikefarah's yq beside Universal Ctags, each optional. `test.sh` runs every check in four modes: all tools, and each of ctags, yq and mdq absent.
  - A small-model suite, `facilitated-waterfall/eval/` (Task 028), which never calls a model: you drive every session. `run.sh prepare [--models] [--scenario] [--runs]` makes a run dir per cell, each with a `/tmp` copy of a committed fixture workspace and a `prompt.txt` with the line to type; you open each Claude Code session yourself, on Opus 5.5 (Haiku, the local model and Sonnet were dropped). A run dir that already exists is kept. `run.sh judge` takes each driven session's transcript from `~/.claude/projects/`, and `extract.py` judges it deterministically from the transcript, the fixture's final state and `sp check`. `run.sh report` prints the table; a cell under 3 runs stays `open` until the 2-of-3 bar is met or out of reach. `test.sh` tests the suite with hand-made transcripts and a stub `claude` that proves nothing starts a session. It lives outside `scripts/`, so it is never installed.

- Compounding workspace knowledge: the per-workspace loop now distils rather than piles up.
  - `note` entries carry `Because:` (a reason, or "not recorded"), a maturity `Stage:` (`provisional · established · canonical · superseded`, separate from the `(unverified)`/`(stale)` freshness markers), and a model-proposed `portable` tag. `gotchas.md` entries take the Moment / Reflex / Instead / Because shape. `recall` reports stage alongside freshness.
  - `note prune` applies a cut test after re-verification, "has this changed a decision recently?", and loudly demotes or retires true-but-idle entries.
  - `done` now means *effect observed*, recorded as a `docs/tasks/LEDGER.md` line, and `implemented` means mechanics verified. No skill writes `status:` on Directions, Epics, Tasks or Plans. `what-next` surfaces Tasks awaiting an observed effect, ranked below the frontier. `implement` states what would show the effect. An `effect not achieved` line is a `bottom-up` trigger.
  - `bottom-up` records read depth (FULL / PARTIAL / NOT_READ) before acting on a resumed probe, and writes reconciled probes to `docs/probes/LEDGER.md`.
  - Optional `intent:` frontmatter, written by `shape`, `breakdown`, `plan` and `top-down`. `bottom-up` and `what-next` compose it into one sentence per level up `relates`, and report missing levels as gaps.
  - `review`, `audit-doc`, `supervise` and the `conventions` audit tag each finding `CONTEXT-GAP` / `JUDGMENT-GAP` / `UNCLEAR` and end with a count line.
  - `conventions` gains "Depth & autonomy": autonomy scales to tier, and plan depth follows author-blind risk, not importance. `supervise` gains an **Auto-continue** class that is recorded without a gate.

- The waterfall carries the knowledge loop (Direction 003, in progress).
  - `facilitated-waterfall/scripts/nav`: one POSIX `sh` + `awk` script that answers where code is defined (`def`), which live docs mention it (`docs`, `module`, `file`), which doc mentions resolve to nothing (`unresolved`), and the intent trace (`trace`). One tags file per workspace, at `<git-common-dir>/nav/tags`, regenerated lazily on change. Sealed docs (closed probes, ledgered Plans, superseded ADRs) are lookup-only. It uses Universal Ctags when found, and falls back to grep. Both directions read one link table, which links a mention only on evidence: an anchor (`` `Sym` (path) ``, a qualified name, a path), a unique identifier-shaped name outside tests, or code citing the doc ("ADR 0042"). Every other mention is counted as unlinked, with a reason, rather than guessed. Every answer reports tiers and an estimated size against a budget share. Fixture tests are in `scripts/test.sh`.
  - The knowledge base becomes the **handbook**, `docs/handbook/`, with five files: `glossary.md` is dropped, terms go to `docs/CONTEXT.md`, and `map.md` keeps purpose and entry points only. New anchors name symbols (`` `Symbol.member` (path) ``), not lines. A probe id can be an entry's warrant, and `index.md` records `last pruned`. An existing `docs/knowledge/` is treated as research and never written to. `conventions` states the contract once.
  - A probe's close deposits into the handbook. `bottom-up` Reconcile now gates on a **Deposit** line. Lessons from the Findings become `provisional` entries with the probe as warrant. Entries the probe relied on are promoted, and wrong ones are fixed or removed. When the area is over a quarter of its inheritance share, or the close completes an Epic or Direction (a fence), the cut test runs over that area's entries only. The procedure is stated once in `conventions` → Handbook → Deposit at a close.
  - Nothing leaves the handbook except into a probe. `note prune` moves every removed entry, verbatim with its reason, into a probe (its own `probe-DATE-handbook-prune` when none is open) instead of deleting it.
  - `nav` prints a `handbook` footer line: the handbook entries linked into the answer, their size, and whether they exceed a quarter of the role's share. Fixed: a hinted anchor (`` `Sym` (path) ``) could be reported as a `hint-miss` when an unhinted mention of the same name came first.
  - `install.sh` links each namespace's `scripts/` at `~/.agent-skills/<namespace>/scripts/`, and checks for Universal Ctags: it asks before installing it (brew, apt, dnf or pacman), only prints the command when not run from a terminal, and warns when a non-Universal `ctags` shadows it on `PATH`. Declining leaves `nav` on its grep fallback.
  - Skills read at **inherit points**, moments they already pass through: `bottom-up` Phase 2, resume, a new module in Phase 3 and an unsituated file in Phase 4; `top-down` at entry and before an ADR; `plan` and `implement` per file in Phase 1; `review`, `audit-doc` and `supervise` per changed file. Each calls `nav` on the target path, reads by tier within the budget share, trims and says so when over it, and states read depth at entry, not only on resume. Without `nav`, the text rules apply. The procedure is stated once in `conventions` → Handbook → Inherit.
  - The product layer joins the loop. `nav docs D-NNN` (or `X-NNN`) gives the `docs/PRODUCT.md` row, what supersedes it, and the docs citing it as `PRODUCT.md#D-NNN`; a bare id is not counted as a citation. `reflect` takes inherit points at Situate and on resume (it now has a resume rule with read depth), finds Affected artifacts through `nav`, and its close deposits product practice into the same handbook, gated by a Deposit line in **Changes**. That deposit is the one exception to confirm-before-write. `direct` takes an inherit point at entry and never deposits. A Task that serves a Story has its effect line judged against the Story's Outcome; `effect not achieved` stays a `bottom-up` trigger, and its climb reaches the Story. Fixed: `nav file` failed on a file with no definitions and no linked docs, such as any Markdown file.
  - `note backfill` replays a workspace's history into the handbook, once per repo, at the user's request. It runs as its own resumable probe: a replay list of closed probes (oldest first, by close date) with fences interleaved, processed about 8 at a time, each batch a checkpoint. Each probe runs Deposit at a close: lessons, not Findings; anchors that no longer resolve are not deposited; old commands are never re-run; a later probe that uses or re-confirms a lesson is its promotion warrant. The cut test runs at each fence. `docs/knowledge/` is harvested for practice lines and left in place. No `intent:`, effect or `status:` lines are written.
  - `nav` prints its summary (`budget`, `handbook`, `always`) right after the header, and definitions last, so a caller's `| head` keeps the budget. The first inherit point of `bottom-up`, `top-down`, `plan`, `implement` and `audit-doc` names `nav`'s path (`~/.agent-skills/facilitated-waterfall/scripts/nav`, not on `PATH`). `install.sh` warns when Claude Code declares no `AGENT_CONTEXT_TOKENS`. `note backfill`'s close asks for the smallest client window instead of skipping the per-area budget check.

- `product-waterfall/` made platform-agnostic and hooked into facilitated-waterfall.
  - All product artifacts are files under `docs/`: `docs/PRODUCT.md`, `docs/product/{directions,epics,stories,probes}/`. Tracker calls (JQL, ticket creation, labels) removed; an optional `tracker:` frontmatter key links out instead.
  - Resolved decisions and product-level exclusions get stable ids (`D-NNN`, `X-NNN`) that artifacts cite in `relates` as `docs/PRODUCT.md#D-NNN`.
  - The two waterlines stack, with the Story as the seam. `direct` stops at Stories and offers `top-down`. `top-down` accepts a Story as entry and hard-stops into `reflect` on a PRODUCT.md conflict. `bottom-up` climbs past the engineering line and hands product-level conflicts to `direct` Refine or `reflect`. `reflect` gains a Propagate phase that lists affected artifacts in both layers.
  - Stories/Epics are editable in place until something relates to them, then change through a `Revisions` section.
  - `conventions` gains a product-alignment audit; FW `conventions` audit flags engineering changes that cross the product line.
  - `what-next` surveys the product layer: childless product Directions, Stories with no FW work, and open probes in either layer.

- `facilitated-waterfall/` namespace: an append-only documentation system implementing the Direction → Epic → Task → Plan → Code pipeline.
  - `shape` — define a Direction (Problem · Appetite · Out of scope · Success signal · Constraints).
  - `breakdown` — decompose a Direction into Epics, or an Epic into Tasks.
  - `design` — interview-driven design decisions, recording ADRs sparingly.
  - `plan` — turn a Task + ADRs into concrete, verifiable steps.
  - `implement` — implement a Plan and verify against the Plan and its ADRs.
  - `audit-doc` — read-only check that an implementation stays inside its governing documents.
  - `what-next` — recommend the best next action by walking the `relates` graph and codebase.
- `general-usage/` namespace: skills usable outside the waterfall, able to feed into it.
  - `note` — record what a session learned into a self-improving knowledge base: a fixed six-file store in `docs/knowledge/`, harvested from the conversation, verified, routed, and pruned to stay current.
  - `recall` — load knowledge relevant to a query from the `note` store before starting work; the read half of `note`.
  - `review` — review code changes or waterfall documents.
  - `simulate` — trace every execution branch of a target and write findings out.
  - `supervise` — iterative implementation review with fresh subagents.
  - `survey` — honest landscape assessment of the current project.
  - `to-waterfall` — promote conversation findings into waterfall artifacts.
  - `zoom-in` — drill into a plan's details.
  - `zoom-out` — question whether a direction is worth pursuing.
- `install.sh` — idempotent installer with client detection for Claude Code / VS Code, Cursor, and OpenCode.
- `README.md` and `CHANGELOG.md`.

### Changed

- Skill names prefixed with their namespace (`facilitated-waterfall-*`, `general-usage-*`) to avoid collisions across clients.
- `what-next` dropped explicit status tracking in favor of deriving the frontier from the `relates` graph and codebase evidence.

### Fixed

- `sp tree`: a Plan that relates to several Tasks counts toward each of them. Before, only the last Task in its `relates` was credited, so another Task under it read `0/1 plans implemented` while its Plan was listed as `[implemented]`. ADR 0004 counts every Plan relating to a Task. Found from the `sp log`.
- `sp trace`: a link into another workspace (`repo:id`, or a path outside `docs/`) is reported as `another workspace: … (not followed)`, as `sp check` says it, instead of `broken link`. A probe or ADR in another workspace is passed over like a local one. Found from the `sp log`.
- `sp trace`: a quoted `id:`, `title:` or `intent:` is shown unquoted, as the index reads it. Before, `id: "007"` was shown as `"007"`, and the quotes were copied into the next call (`sp tree '"021"'`). Found from the `sp log`.
- `sp`: a cut answer suggests what its verb takes. Only `docs`, `file` and `module` read `--type`; `tree` suggests `sp tree <descendant id>` or `--all`, and the other verbs suggest `--all`. Before, every cut answer said "narrow with --type", which `tree` silently ignored. Found from the `sp log`.
- `sp`: a symlink in a git workspace is no longer indexed as a second file. In this repo, `nav -> sp` made `sp def` answer every definition in `sp` twice and `sp module` list both. Found from the `sp log`.
- `sp` call log: a call that runs `sp` again (`migrate` checks its preview copy) records the workspace it was called in, not the copy's temporary directory. The nested call no longer overwrites the record's workspace. Found from the `sp log`.
- `sp`: a reference that names no doc now says how to recover instead of pointing at `sp check`, which never lists a doc that doesn't exist. A missed kind-prefixed id names the highest id of its kind (`the highest adr here is adr-0030`) or says that kind has none, and other refs are told to use a kind-prefixed id or path. `show`, `outline`, `tree`, the write verbs and `sp check <id>` share the message. Found from the `sp log`.
- `sp`: heredoc terminators are no longer indexed as definitions. Universal Ctags tags each `<<EOF` as `kind:heredoc`, so `sp module` on a shell directory listed every file's sample names as `EOF, EOF, …` with inflated counts, and `sp def EOF` answered with a "definition". The tags are dropped when the index is built, so `module`, `file`, `def`, `unresolved` and the doc-to-code links all stop seeing them. Found from the `sp log`.
- `sp`: a kind-prefixed id names an artifact of that kind, never a doc outside the kind directories that happens to carry the same `id:` (a nested fixture's, say). Before, in a repo whose own docs still had path ids, `sp show adr-0001` read the nested doc, and `sp new … --relates adr-0001` wrote its path into the new doc's links, with no warning.
- `sp trace` on an id that names no doc now says so as `show` does (`names no doc: the highest task here is …`, exit 2), instead of a `broken link` row with exit 0. A broken link further up the trace is still a row. `sp file` given an artifact id says it takes a path and names the path, or that the id misses.
- `sp`: `help` is reserved in any argument slot, as `--help` already was. `sp new probe help` printed nothing useful and wrote a probe titled "help"; it now prints `new`'s page and writes nothing.
- All skills given YAML frontmatter (`name` + `description`); the installer now validates it for OpenCode and skips namespaces with missing frontmatter.
- OpenCode skills installed as `<namespace>-<skill>/SKILL.md` subdirectories rather than flat `.md` files, matching OpenCode's loader.
